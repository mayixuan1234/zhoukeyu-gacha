# 抽抽乐记录器

> 个人项目 | v6.1 | 1000+ 用户 | 已上线

面向粉丝社群活动场景的**在线盲盒抽卡记录管理工具**。支持三种录入方式（Excel 导入 / OCR 识别 / 手动输入），提供全维度数据统计和可视化。

## 在线访问

🔗 [https://zhoukeyu-gacha.pages.dev/](https://zhoukeyu-gacha.pages.dev/)

## 🧠 项目回忆：怎么开始的

2026年7月，周柯宇粉丝社群发起"爱意正值炽夏"抽抽乐盲盒活动。活动持续半个月，涉及几十种卡牌、复杂满赠规则、多时段限时奖励。

社群运营方用 Excel 手工统计每个用户的抽卡记录——手工数有几张 R 卡、SR 卡，手工算满赠门槛达没达标。几百个用户下来，每天对账到凌晨。

看到这个痛点，花了一个晚上写了个 HTML 页面：读取 Excel，自动归类统计。第一个版本只有"导入 + 看表格"两个功能，在超话发了个帖子说"我做了个工具"，没想到第二天就有几十个人在用。

**这就是 v1 —— 2026年7月13日。**

### 从网页版迁移数据

APK 和浏览器是独立的存储空间。迁移步骤：

1. 手机浏览器打开网页版 → **备份/导出** → 下载 JSON
2. 打开 APK → **导入** → 选刚下载的 JSON
3. 完成。之后只用 APK，网页版留作备份入口

## 功能模块

### 数据录入（三种方式）

| 方式 | 说明 | 为什么做 |
|------|------|----------|
| Excel 导入 | 批量导入粉丝在微店/接龙平台购买的抽卡数据 | 用户最初的数据就在 Excel 里，最快上手 |
| OCR 识别 | 上传"我的抽卡"截图，Tesseract.js 自动识别卡牌信息 | 有些用户手机里只有截图没有 Excel |
| 手动录入 | 表单逐条输入，支持格式清洗（如 "R44、SR8、R25"） | 抽得少的用户不想折腾 Excel |

### 数据展示

- **卡片图鉴**：全部卡牌陈列（R/SR/SSR/UR/浪漫疯等），含概率和拥有状态
- **抽卡统计**：个人总抽数、持有率、花费统计、抽卡时间线
- **排行榜**：用户间抽卡数量和收集率排名（社区互动核心功能）
- **全站数据**：111,801 总抽数 | ¥737,886 总销售额（从 Cloudflare Worker 汇总）

### 运营功能

- **公告系统**：管理员（我）发布活动公告、规则更新
- **更新日志**：每个版本改了什么都记录，新用户打开能看到变化
- **数据同步**：Chrome 扩展辅助批量从网页抓数据
- **碎卡兑换**：非酋机制——重复卡太多可以兑换指定卡

### 兼容性

- **微信内置浏览器适配**：最坑的一块——微信内核和标准浏览器行为不一致
- **移动端响应式**：大部分用户用手机打开
- **PWA 离线支持**：加了 service worker，无网也能打开

## 🔧 技术栈详解

| 层级 | 技术 | 为什么选它 |
|------|------|-----------|
| 前端 | 原生 HTML/CSS/JS | 不需要框架学习成本，一个文件写完部署 |
| 图表 | Chart.js | 需要饼图、柱状图、折线图，CDN 加载就行 |
| OCR | Tesseract.js | 浏览器端 OCR 的唯一选择，虽然慢但能用 |
| OCR 代理 | Cloudflare Worker | 避免 API Key 暴露在前端代码里 |
| 存储 | localStorage | 用户数据存自己手机，不用服务器 |
| 部署 | Cloudflare Pages | 免费、自动 HTTPS、全球 CDN |
| 扩展 | Chrome Extension | 从网页批量抓取抽卡数据 |
| Android | WebView + aapt2 | 不学 Android Studio，命令行直接打包 |

### 为什么是单文件 SPA

244KB 的 `index.html` 包含了所有 HTML + CSS + JS。好处：

1. **部署简单**：拖到 Cloudflare Pages 就上线，不需要构建工具
2. **修改快**：一个文件改完保存刷新，不用 `npm run dev`
3. **给用户方便**：Chrome 扩展只需要读一个文件就能拿数据
4. **代价**：代码结构越来越乱，244KB 的单文件调试很痛苦

## 🧪 踩过的坑（面试能聊）

### 1. 微信内置浏览器清 localStorage

微信切换账号时，X5 内核会**清空整个 localStorage**。用户的抽卡记录全丢。

**解决**：加了强制备份提醒——检测到数据为空的瞬间弹窗"你的数据好像丢失了，建议尽快备份"。同时做了剪贴板备份方案（因为微信内核 `navigator.clipboard` 也不兼容，得用 `document.execCommand('copy')` 降级）。

### 2. Tesseract.js 加载慢 + 安全风险

Tesseract.js 的 WASM 文件有几十 MB，直接前端加载网页卡死。而且训练数据和 API Key 不能放前端。

**解决**：Tesseract.js 按需加载（`createWorker` 懒加载），OCR 调 Cloudflare Worker 代理。Worker 侧做鉴权 + 请求频率限制，避免被恶意调用。

### 3. OCR 识别准确率

截图里的文字经常识别错——"SR"识别成"5R"、"R25" 识别成"R2S"。

**解决**：在 JS 层加了后处理清洗规则（正则替换已知错误模式），用户可以手动修正识别结果。

### 4. 排行榜数据造假

localStorage 存本地，理论上用户可以改 localStorage 伪造数据。

**解决**：排行榜加"云端总抽数"对照（从 Worker 汇总的真实数据），差异太大的标红提示。

### 5. Chart.js CDN 离线不能用

早期版本 Chart.js 走 CDN，离线打开图表全白。

**解决**：把 `chart.umd.min.js` 下载到本地打包进 HTML，离线也有图表。

### 6. APK 签名证书管理

Android 覆盖安装要求签名一致。证书丢了 → 必须先卸载 → 数据全丢。

**解决**：`focus.keystore` 备份到多台设备 + 网盘。密码 `focus2026`，两个 App（抽抽乐 + 专注工作台）共用一个。

## 关键设计决策

| 决策 | 原因 |
|------|------|
| 纯前端、不用服务器 | 零成本、零运维。用户数据存本地还解决了隐私顾虑 |
| 不做账号系统 | 粉丝社群场景，用户不想注册——注册 = 流失 |
| OCR 用 Worker 代理 | Tesseract.js 前端的 API Key 是裸奔的 |
| 做排行榜但接受数据不精确 | 社区互动的价值 > 数据精确性，加云端对照降低造假 |
| 做 APK 但不上架应用商店 | 上架要审核、要给 Google $25，用户直接下载 APK 更快 |
| 单文件 SPA 不拆模块 | 快速迭代 > 代码整洁。v1→v6.1 每天都在改 |
